# 采单 · 采购协同

本地运行的客户询价与跨平台采购管理系统，第一版 V0.1。React + Vite 前端，Python 标准库 HTTP 服务与 SQLite 数据库。

当前定位为**单人、本机试用版**，不是已接通购物平台的生产系统。业务数据初始为空，测试数据保存在隔离数据库。

## 启动

Windows 客户端：双击根目录的 **启动客户端.cmd**。可在客户端登录淘宝、打开订单详情并提取采购信息；多包裹逐个核对登记。使用同一份网页构建及原有业务数据库。详见 [客户端说明](./desktop/README.md)。

在项目目录运行：

```powershell
.\start.ps1
```

打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。关闭服务终端或按 Ctrl+C 停止服务。

启动脚本优先使用项目 `.venv`，其次使用此电脑现有 Codex Python 运行时，最后使用 PATH 中的 Python。已有 `dist` 时直接启动；修改前端后请先运行 `npm run build`。脚本不会擅自安装系统级软件。

在另一台电脑安装：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
npm ci
npm run build
.\start.ps1
```

需要 Python 3.11+、Node.js 20.19+ 或兼容的更新版本。本次使用 Python 捆绑运行时和 Node.js 24 验证。依赖由 `package-lock.json` 锁定；可用 `.data/npm-cache` 作为当前项目的 npm 缓存。

## 操作顺序

1. 先从“客户订单”右上角进入“客户列表”，维护客户、联系人、电话和收货地址。在“询价导入”上传 `.xlsx` 或文字型 PDF，选择客户；仅一个联系人/地址时自动带出，多个时选择。电话随联系人带出，地址允许按订单修改。PO 可从页头或“单据编号”等明细列提取，也可手动填写；出现多个 PO 时先筛选对应明细。核对后保存。导入时也可直接新增客户。资料尚未完整时点击“暂存未完成草稿”，稍后从询价导入页左侧恢复继续填写，也可删除不再需要的草稿；正式订单仍需通过必填信息和核对确认。
2. 在“客户订单”打开详情，填写报价并确认。修改已确认报价时先创建新版本。
3. 在“采购记录”登记平台订单，选择客户料品，填写需求数量、实际包装数量和分摊金额。实付款应包含运费并扣除优惠，分摊合计必须与实付款一致。
4. 在“采购记录 → 物流包裹”选择采购明细，登记包裹。核实实际状态后更新轨迹；签收时填写真实日期。
5. 在“送货单”选择已发货料品和本次开单数量，选择合并或按包裹分别开单，填写公司抬头后生成与导出。
6. 在“采购发票”记录索票进度，收到文件后上传并分配金额。全部收齐后自动解除催票待办。

默认全部采购数量都已装包且全部包裹签收后，按最后签收日期加 7 天生成提醒日期；到期当天即进入提醒。无完整签收信息时不猜测日期，可手动指定。部分收票继续提醒，“不需开票”必须记录原因。

## 数据与备份

管理员可在“设置 → 备份与恢复”下载完整 ZIP 备份，或导入备份替换当前业务数据。备份包含数据库及其引用的附件，包括账号、公司资料、印章、订单、采购、发票和送货单。网页恢复限制为 ZIP 100 MB、解压内容 512 MB；恢复前检查数据库结构、完整性、外键及附件 SHA-256，校验不通过不会替换业务数据库。恢复操作与服务内其他请求互斥，期间请等待。

更换服务器时：先在新服务器安装与备份数据库结构兼容的采单版本，设置持久化数据目录，使用新实例管理员登录并导入 ZIP。恢复成功后，改用备份中的原账号和密码登录，并将客户端连接地址改为新服务器。IP 和数据目录可以变化；淘宝登录会话不包含在业务备份中。

恢复前系统自动将当前完整数据保存到数据目录的 `backups/before-restore-*.zip`。恢复后清除所有旧登录会话，未被恢复数据库引用的旧附件保留但不会出现在业务中。若系统已无法启动，可先新建可运行的实例，再在设置中导入备份。请将下载的备份另存到其他设备；服务器上的安全备份不能防止同一磁盘损坏。系统版本升级通过飞牛 Docker 操作，不提供网页程序更新。

- 数据库：`.data/caidan.sqlite3`。
- 附件：`.data/attachments/`，按文件摘要去重保存。
- “本机工作区”提供完整备份下载，ZIP 包含数据库及附件。
- 恢复时先停止服务，将当前 `.data` 整体复制到另一个备份目录，再把备份中的 `caidan.sqlite3` 和 `attachments` 解压到一个**新的空目录**。将 `CAIDAN_DATA` 指向该目录后启动，避免旧 WAL 文件与恢复库混用。
- 示例：`$env:CAIDAN_DATA='D:/caidan-restored'; .\start.ps1`。
- 不要在服务运行时直接替换数据库文件，不要将 `.data`、实际客户资料或平台凭证提交到 Git。

## 开发与测试

```powershell
# 终端 1：后台
python -m server.app --port 8765

# 终端 2：前端开发
npm run dev

# 构建与测试
npm run build
python -m unittest discover -s tests -v
```

如 PATH 中的 Python 不可用，请替换为 `.venv/Scripts/python.exe` 或启动脚本检测到的 Python 路径。

测试使用临时 SQLite 数据库，覆盖超量采购/装包、订单去重、报价版本、金额核对、发票提醒、部分收票、导出字段、送货单作废、原始快照、跨客户合并拦截、HTTP 回滚、来源校验与备份恢复。

## 当前边界与下一阶段

### Docker 集中部署目标

后续部署时，订单、采购、送货单、附件、操作日志和完整备份统一保存在服务器挂载的持久化数据目录（计划使用 `CAIDAN_DATA=/data`）。网页端和桌面客户端访问同一服务端，不再各自创建业务数据库。服务器数据目录应独立于容器镜像，升级容器时保留；备份与恢复覆盖数据库和附件。

当前版本仍是本机模式，**不能直接将容器开放给其他设备使用**：HTTP 服务只接受本机地址，桌面客户端会启动自己的本机服务。正式迁移前还需实现受控的远程连接、HTTPS、登录与访问控制、淘宝提取结果的安全写入，并验证多设备同时操作和备份恢复。淘宝网页登录会话仍留在执行提取的客户端；提取到的业务信息写入服务器。

- **购物平台官方接口、实时物流服务尚未接通。** 当前不自动登录购物平台，不自动下单、付款或向店铺发消息。需要先确认采购账号类型、取得平台/物流服务授权，再实现连接器并实测。
- **扫描 PDF、截图及发票 OCR 尚未接入。** 图片可作为附件保存，字段需人工填写。客户文字型 PDF 使用规则提取；复杂跨页表格可能需要补录，不能承诺任意版式自动识别。
- 多个工作表可逐个追加或覆盖明细，暂不支持多页一键合并；已导入客户 PO 重复时会拦截，客户订单修订对比尚未实现。
- 尚未实现客户模板记忆、历史采购推荐、平台退款自动执行、红字发票自动开具、有下游依赖的采购明细直接改写、已采购客户料品结构修订、批量打包下载送货单。
- 可批量生成多张送货单，目前逐张导出。采购成本显示实付款分摊金额，已分开记录供应商退款实际到账，尚未加入精确税务利润模型。
- 原件支持打开/下载及提取文本查看，尚未实现 PDF 框选定位、Excel 单元格高亮对照。
- 仅绑定 `127.0.0.1`，无多人登录、权限与公网部署；手机尺寸布局已设计，但其他设备尚不能连接。开放局域网前应补充身份认证、权限、HTTPS 和运行维护配置。
- Python 标准库 HTTP 服务适用于本机试用，生产部署应迁移到受维护的应用服务器并补充鉴权、分页及监控。
