# 采单 Windows 客户端

双击项目根目录的“启动客户端.cmd”。本机服务会自动启动，退出客户端后自动停止；无需安装 Python 或 Node.js。现有网页与客户端共用项目 `.data` 中的数据库及附件。淘宝登录状态位于 `.data/desktop-profile`，不包含在业务备份里。

在客户端顶部切换“淘宝订单”，扫码或自行登录淘宝。进入一笔订单详情，点击“提取当前订单”，回到采购表单核对店铺、订单号、金额、日期、商品参考与运单。选择客户料品及对应淘宝商品后，页面展示的商品金额会填入分摊金额；未识别到金额时可留空保存。对应客户需求数量仍须人工核对。

采购保存后，提取到的快递公司和运单号直接显示在采购记录的“物流 / 运单号”列，无需核对登记包裹内容。多个包裹对应哪些客户料品仍不能自动判断；如需记录具体装包数量，可单独登记。客户端运行期间会使用现有淘宝登录会话，启动后及每 30 分钟按已保存的订单链接重新检查；新运单和页面可识别的物流轨迹会补充到原采购单，登录过期或页面识别失败时保留原记录并在采购明细显示检查结果。关闭客户端后不执行定期检查。再次手动提取已登记订单，会提示确认补充提取信息，不会新建重复采购单或覆盖采购金额。

客户端运行并保持淘宝登录时，启动后及每 30 分钟会在隐藏页面检查已保存的淘宝订单。尚无运单号的采购单可补录页面显示的单号；已有运单号的采购单只同步这些单号的物流状态与页面可见的轨迹，不自动增加新单号。已登记包裹按运单号关联更新，重复节点不会再次写入；未分配的包裹仍须人工确认料品数量。登录失效、出现验证或无法识别页面时，采购详情显示同步失败，原物流记录保持不变。普通网页端不会执行后台检查。

支持电脑淘宝订单详情页 `trade.taobao.com/trade/detail/trade_order_detail.htm` 和天猫订单详情页 `trade.tmall.com/detail/orderDetail.htm`。登录、验证码由用户自行完成，页面未显示的字段不推测。天猫页面可识别订单号、实付款、创建日期、店铺及页面展示的运单，商品信息仍需人工核对。页面结构变化可能导致缺失字段，需人工补录。未保存的提取结果保留在客户端内存，关闭客户端时会提示放弃；已经保存的商品和物流参考随数据库持久化。收件人、电话、地址不在提取字段内。

## 分发

当前更新包位于 `release-manual-drafts/Caidan-win32-x64`，是完整免安装程序目录，需要整体复制；项目根目录的“启动客户端.cmd”会优先启动该版本。直接运行其中的 `Caidan.exe` 时，新电脑默认使用 `%APPDATA%/caidan-procurement/business` 保存业务数据；本项目的启动脚本显式指向原来的 `.data`。可通过 `CAIDAN_DATA` 指定其他业务目录，通过 `CAIDAN_PROFILE` 指定独立登录配置目录。不要分发 `.data`、淘宝登录配置或真实客户资料。

发票自动获取需在客户端内登录淘宝后执行。选中采购单后，系统下载尚未获取的 PDF / OFD 并关联采购，显示“已获取”，等待人工确认收票；等待确认期间不重复下载。支持新窗口下载、PDF 预览链接及无扩展名的 PDF / OFD 响应。错误页不会作为发票保存，获取失败时显示原因。普通网页可查看已下载文件及确认收票，不共享客户端淘宝会话。

客户端启动约 10 秒后及每 30 分钟，自动检查需要获取发票的淘宝／天猫采购记录，再更新物流；两项任务串行执行。无需开票、已收齐和文件已下载待确认的采购记录会跳过，无需保持列表勾选。未开票或下载失败的订单在下次检查时重试；文件下载成功后提示人工确认，不会自动确认收票。手动“获取所选发票”仍只处理勾选的订单，并在当前后台步骤完成后优先执行。登录失效或出现验证时仅提示，不自动切换当前页面；登录恢复后下一周期继续检查，也可手动获取。关闭客户端后停止检查，普通网页不能独立定时获取。

询价导入支持单个最大 100 MB 的 `.xlsx` 和文字型 PDF，网页与客户端使用相同文件大小校验。

## 服务器常驻（无人值守）

在作为服务端的电脑上让客户端常驻，其他设备就只需要浏览器：自动同步和网页端"立即同步"都由这台机器上的客户端执行，其他电脑、手机不必安装客户端。

- 客户端：托盘菜单的"开机自启"写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`（`Caidan.exe --startup`）。关闭主窗口只是隐藏到托盘，不影响同步；真正退出要用托盘菜单的"退出采单"。
- 局域网网页服务：开机自启项 `CaidanLanWeb` 运行 `.venv\Scripts\pythonw.exe scripts\lan-server.py --port 8765 --host 0.0.0.0`，没有控制台窗口，输出追加写入 `.data\lan-server.log`；需要停止时在任务管理器结束 pythonw.exe，或改用"启动局域网访问.cmd"手动前台运行。
- 两条自启路径必须指向同一份数据：本机已把 `CAIDAN_DATA`（`E:\SPLC\.data`）与 `CAIDAN_PROFILE`（`E:\SPLC\.data\desktop-profile`）设为用户环境变量，所以无论从启动脚本还是开机自启项启动都使用同一个数据库。若要迁移数据目录，这两个变量必须同步修改，否则客户端会另建一份空数据库。
- 常驻的前提是 Windows 会话保持登录：机器重启后需要有人登录（或配置自动登录），并且淘宝登录过期后自动同步会失败并在采购明细保留原记录，需要在客户端窗口重新登录淘宝。

## 开发、测试、重新打包

```powershell
npm run build
npm run desktop
npm run test:desktop-policy
node --test tests/desktop-invoice-schedule.cjs
node tests/desktop-smoke.cjs
.\desktop\build.ps1
```

打包脚本需要 Python（安装 `requirements.txt` 中的依赖）和 Node.js。优先使用 `.venv` 或本机已存在的 Python 运行时，亦可传入 `-Python`。Electron 运行时由其发布清单的 SHA256 校验；下载受限时可设置可信镜像 `ELECTRON_MIRROR`。首次开发启动若提示沙箱不能读取运行时，可对 `node_modules/electron/dist` 和 `desktop` 两个程序目录授予 `ALL APPLICATION PACKAGES` 的读取/执行权限，不要关闭沙箱或对业务数据目录扩大权限。

`desktop-smoke.cjs` 使用临时数据库、独立登录配置和合成订单页面，不访问真实淘宝账号。设置 `CAIDAN_TEST_EXE` 可验证打包版；设置 `CAIDAN_QA_DIR` 可指定测试截图目录。真实淘宝登录兼容性和会话续期需另行人工验收。


客户订单、采购记录和客户列表默认每页 50 条，可在列表底部切换为 30、100、200 条。筛选范围包含全部记录。客户订单与采购记录的全选仅作用于当前页，翻页、改变条数或筛选时清空勾选。列表行高固定为 50px，较长内容截断，完整信息可在详情查看。

客户列表在“收货地址”右侧提供“开票信息”：点击“填写开票信息”维护客户发票抬头、纳税人识别号、注册地址和电话、开户银行和账号、收票邮箱。保存后显示“已维护”，可继续查看或编辑；资料单独保存，修改联系人及收货地址不会覆盖它。填写发票抬头后，可复制当前资料或导出 PDF、Excel；导出文件以发票抬头命名，复制与导出不自动保存修改。

## 订单变更与售后

- 普通用户可删除录错、重复录入且没有后续业务的客户订单、询价草稿或采购记录。删除移入回收站，管理员可恢复；已有包裹、送货、收票或业务处理记录时，保留历史，改用对应处理或归档。
- 客户订单的“取消／售后”按料品数量登记取消未发货、退货退款、换货、仅调整金额。已开送货单先占用数量，实际发出后需在送货单确认发货；历史送货单请核实实际情况再确认。
- 退货需关联原实际发货明细。申请中的数量也占用可退额度；收到退货后登记累计实收数量。换货另选对应售后记录生成补发送货单，退回不会自动增加正常交付额度。
- 采购明细中的“采购处理”按数量登记取消采购、退供应商、转库存或转其他订单；可拆分数量办理不同去向。共享采购只调整对应明细，完成后更新有效采购数量和成本。库存可再次转入需要采购的订单。
- 料品主数据集中在“产品库”：新建和维护料品、客户/供应商型号对应关系、停用与库存汇总。订单和采购按型号自动匹配同一料品编号，匹配到多个或没有匹配时可以人工选择或先建档。
- 采购明细可选“收货方式”：直发客户沿用包裹物流与签收；入库的采购到货后在“库存 → 登记入库”核对数量、型号、单位和库位。不关联客户订单时，在采购登记里“从产品库选择料品”即可登记备货采购（固定入库）。
- 订单明细显示现存量、可用库存、预计可供量和本单缺口，可在订单详情“占用库存”，再“安排出库”；出库扣减库存、结转移动加权平均成本并生成送货单。提前关联订单的入库数量自动转为该订单的库存占用，公共备货进入可用库存。
- 实际收款、客户退款或应收调整、供应商退款到账由管理员确认。金额尚未确认、退货未收齐、关联采购未处理或换货未发完，不能完成售后。已关联发票的退款需记录发票调整核对结果，原发票和附件继续保留。
- “已归档”保留统计、历史和待办提醒。管理员更正需填写原因；已有后续业务的记录须先处理下游依赖。系统记录业务结果，平台退款、退货和发票调整需经办人实际办理。

自动同步可在“设置 → 自动同步”开启或关闭，并设置 1～1440 分钟的间隔（默认 30 分钟）。保存后客户端在 15 秒内读取新设置，当前检查会完成后再停止。已知包裹全部签收的采购单自动停止物流检查，发票仍按需获取；手动获取发票不受开关影响。

自动同步同时采集尚未登记的淘宝订单为采购草稿，首次限定最近 7 天（含今天）。后续从上次成功扫描日期继续并重叠一天查漏；按平台订单号去重，已有采购和草稿不重复新增。详情首次提取包含页面可见商品与物流，未全部签收的草稿继续补充物流。网页端采购记录顶部可关联料品后登记；草稿不占采购数量和成本。扫描失败可在“设置 → 自动同步”查看结果，登录/验证仍由用户在客户端完成。

采购记录与采购草稿以同级页签切换，各自默认每页 50 条，可选 30/50/100/200 条。同步间隔在“设置 → 自动同步”维护；采购及设置页面每 15 秒更新可见数据。网页服务使用独占端口，重复启动会报端口占用，避免多个实例返回不同版本的数据。

网页采购记录/采购草稿页签右侧的“立即同步”会请求客户端执行一轮采购草稿、发票和物流同步。客户端需保持运行并登录淘宝，15 秒内领取请求；不受自动同步开关或间隔限制。网页显示等待、执行中、完成或失败结果，重复点击不会重复排队。
